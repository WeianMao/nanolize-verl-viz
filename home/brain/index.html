Half the tokens.All the behavior.

A brain matures by pruning the connections it does not use. Nanolize does that for code: it rewrites a bloated repository into a nano one that coding agents read, change and run for fewer tokens.

GitHub is society's brain, and agents now write more of it every day. A brain does not mature by adding connections alone. It prunes the ones it does not use, and what remains works faster. Nanolize does that for code, so every agent that reads, changes or runs it spends fewer tokens.

Writing and checking never meet.

A capable agent can pass a weak test by fitting code to it, loosening it or copying the original. So Nanolize builds a firewall into the workflow, and a verifier that is plain code decides what passes.

Each of these fails. Press one.

  • Rewritten from a contractThe author starts in an empty workspace with the behavior callers rely on: interfaces, defaults, outputs, command-line options. No tests, no history, its own file layout.
  • Hardened, then frozenEach selected feature is switched off in the original. Where no test notices, the test designer writes one. The suite is frozen before any new code is tested.
  • Driven by toolsA controller runs five stages through thirty-nine self-checking tools. It decides what runs next and never reads the source or judges a check.

Point your agent at a repository.

shell
$ git clone <repository> nanolize && cd nanolize
$ python -m pip install -e .   # Python 3.11 or newer
$ nanolize serve               # MCP server for your agent

Plugin configurations for Codex and Claude Code ship with the repository. Ask the agent to nanolize a repository, and three pages keep you in charge.

  1. ReviewStart from Core features or All features, switch optional features on or off on the capability graph, then submit.
  2. RunFollow the stages, repairs, tokens and elapsed time live.
  3. ReportRead the outcome first, then every check, the size breakdown and the repair history.
