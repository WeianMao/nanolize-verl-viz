需要对 nanolize 改动的 bugs

本页问题列表只保留经核对确定由 nanolize 自身引起的 8 项。

编号简要说明
10合法的公开 file URL 测试值被误判为宿主绝对路径；需要区分产品输入与主机位置。
12技能允许的自然语言接口说明未被设计器名称白名单识别；identity、benchmarks、docs 留下测试缺口。文档、契约校验与设计器的接口名称提取规则需要衔接。
13每叶只提供前 40 个迁移目标，后续轮次仅重试已截断的集合，309 个目标始终未分配；完整迁移需要改为分批处理。
14JUnit 解析器超过 20,000 用例即整体返回 unavailable；版本检查有 51,511 用例，缺少完整逐例证据，需要支持大型报告或拆分检查。
16迁移事件以 89 为分母，却列出总计 398 的状态；应分开总量、已分配和未分配。
23修复反馈无法识别普通 pytest setup/teardown 异常的包装消息，逐例解析和输出兜底均可能遗漏异常类型及阶段信息。需要保留最小结构化诊断，供修复控制器正确归因。
24定向复验的检查范围较小，较低的失败计数会重置停滞轮数；应改为同范围比较实际失败消除。该问题影响停滞判断，不等于将未运行检查判为通过。
25只读 reviewer 完成审查并写出文字结论，但 run_agent 回执只返回状态和文件变化，没有把结论或报告引用传给控制器。需要交付经过边界校验的 findings 或可读取的审查 artifact。

21pickle CLI 帮助的 stdout 与原版不同，metadata 场景的结构化观察值中错误消息标点不同，即使进程退出 0，比较仍不通过。最终 candidate-6 为 3/50 检查组通过、47 回归，安装检查 2/2 通过，带失败交付。
22体积缩减包含基准样本、配置、注释和文档删除，三个基准样本减少 22,696 token；剔除 Python 注释/docstring 后保留比例为 35.49%。这些减少不能全算算法压缩，候选未通过行为等价验收。
